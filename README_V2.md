# 印刷工場の対向搬送と機械駆動 V2

提出済みのV1とは別の改良実験です。外壁を除き、車輪で走る2台のAMRが、すれ違えない狭路を挟んで印刷工程の仕掛品を運びます。Jeffが先行・待避・待避車の再進入許可を選び、ViNTとNoMaDが実際の前方RGB画像から局所経路を予測します。

## 印刷工程と今回の範囲

ジョブAは印刷機上の白紙100枚から始まります。Jeffが印刷開始を許可した後、その用紙を実際のローラーで送り、印刷済みになった同じ紙束を接触でAMRへ移載して折り機へ運びます。ジョブBは折り済みの仕掛品100枚として始まり、断裁機へ運びます。各紙束は1.44kg、納期の設定値はAが180秒、Bが140秒です。

Aの印刷→折りとBの折り済み→断裁を工程状態で接続します。今回の終了点ではAは折り済み、Bは後加工済みです。この2搬送を「白紙から新たに200部を完成させた」とは数えません。1ジョブを上流から最後まで通した提出版は、既存のV1に残しています。

紙束は剛体です。接触による搬送・受け渡し、送りローラー・クランプ・ガントリーの駆動を物理計算します。紙の実変形、インキ転写、刃による材料破断は対象外です。

100枚を1つの代表剛体として扱います。印刷機の動作はこの代表体の支持とローラー駆動で検証し、100枚を1枚ずつ分離給紙して印刷ニップへ通す機構は再現していません。`printed`への更新は印刷ジョブの工程モデルであり、実際のインキ転写を計算した結果ではありません。

## 各AIと通常制御の担当

| 担当 | 入力 | 出力と実際の用途 |
| --- | --- | --- |
| Jeff 2B | 現在の天井RGB、仕掛品・納期・車体状態、候補行動 | 新規ジョブAの印刷開始、先行車と待避車の選択、通過後の明示的な再進入許可、停止した学習走行の再試行許可 |
| ViNT | AMR1の前方RGB履歴と局所目標のRGB | 予測点から走行方向を求め、車輪モーターへ指令 |
| NoMaD | AMR2の前方RGB履歴と局所目標のRGB | 予測点から走行方向を求め、車輪モーターへ指令 |
| 通常制御 | 実測姿勢、距離、接触、駆動状態 | 初期の向き合わせ、終端18cmの位置合わせ、最終70cm以内の機械への接近、モーター制御、機械の動作順序、安全停止 |

学習走行中の旋回目標はモデルの予測点から求めます。世界座標の目標へ向かう通常経路制御を、学習走行として表示しません。Jeffの候補が拮抗した場合も入力順で優先車を決めず、許可を保留して再評価します。安全側の制御は停止を指示できますが、優先車を選びません。

この交通整理自体は予約表などのルールでも実現できます。本実験が示すのは、既存の学習モデルを実際の観測・行動ループに組み込み、制約付きの物理系を動かす構成です。ルール方式に対する優位性、汎用的な画像認識精度、産業用の安全性能を証明する実験ではありません。モデルの追加学習は行っていません。

## 実装した機械制約

- AMRは自由基体と4つの車輪関節を持ち、床との摩擦で動きます。運転中に基体や紙束の位置を書き換えません。車輪の駆動上限は各6Nm、昇降の力上限250N、ストローク60mmです。
- 車体幅は0.56m、狭路幅は0.90mです。2台は対向通過できず、相手が実際に待避ポケットへ入るまで進入できません。出口で旋回中の車体との距離も確認します。
- ガントリーには固定脚、Xレール、Y台車、Z昇降部、押し板があります。各軸に速度・力・ストロークの上限があり、Y軸の力上限は125Nです。
- 印刷機は実際に駆動する送りローラーを持ち、用紙との支持・接触とローラーの回転量を確認して印刷済みへ進みます。後加工機には送りローラー、開口を持つ支持台、実際の面取り、駆動クランプがあります。断裁機は南側から受け入れる向きに配置しています。
- 移載ではAMRの昇降台を5mm上げて停止させ、実測した台の高さから押し板高さを決めます。紙束の実測位置と向きから外形を求め、紙の外側に押し板を下降させます。押す前に実際の高さが接触可能な狙いの高さから1.5mm以内にあることを確認し、受入機との接触と位置を確認して納入と判定します。

これらはこのデモ用に設定した値で、実機メーカーの定格値ではありません。

## 動画の読み方

大きな工場映像は表示中のSIM時刻の状態です。その右にJeffの実入力画像を表示し、入力SIM時刻を明記します。下段には各ジョブの現在工程と搬送先、各AMRモデルの入力画像・予測点、車輪の指令と実測、駆動トルク、昇降状態を表示します。「AI予測を走行に使用中」と「直前のAI予測（現在は従来制御/待機）」を区別します。

Jeff欄には実際に返った選択と候補スコアを表示し、モデルが出していない理由文は作りません。通行許可と通常の安全停止は別の欄です。ガントリーには実測位置・目標・駆動力・飽和状態を表示します。

動画はSIMを0.05秒刻みで全フレーム記録し、40fpsで一律2倍再生します。途中の時間省略や場面カットはありません。`frames.jsonl`とデコードした全動画フレームの対応は、下記の監査スクリプトで確認できます。

物理計算中は`overview.mp4`に全カメラフレーム、`frames.jsonl`に同時刻の状態を保存します。終了後に説明表示を並列合成し、元の順序で`demo.mp4`へ書き込みます。`run-v2.ps1`は物理実験・動画合成・全フレーム監査を順に実行します。

## 実行と記録

新しいPCでは、[環境構築手順](docs/superpowers/README_JEFF_RUNTIME.md)に従ってGenesis用の`.venv`を準備し、`setup-jeff-factory.ps1`で推論用の環境とモデルを用意します。本実装は物理計算にGPU0、モデル推論にGPU1を使うため、CUDA対応GPUを2台必要とします。

```powershell
.\run-v2.ps1 -MaxSeconds 360
```

`output/v2/latest_run.json`が今回の出力先を示します。実験ごとに新規フォルダーを作成し、失敗した試行も上書きしません。

- `demo.mp4`: 同期表示付き動画
- `result.json`: 完了判定、実モデルの情報、通行判断、接触・同時搬送の記録
- `frames.jsonl`: 各フレームのSIM時刻、機構状態、紙束姿勢、表示データ
- `navigation/navigation_inferences.json`: 実際の学習推論の入出力と適用状態
- `jeff_*.png`: Jeffに渡した実際の画像
- `source/`と`source_manifest.json`: 起動時のコードとハッシュ

```powershell
.venv\Scripts\python.exe scripts/audit_v2_video.py output/v2/fleet_実行日時
```

実行時間上限に到達した試行や失敗試行を、成功動画として扱わないでください。成功には、2件の物理的な受け渡し、両方の学習モデルの実推論、実接触で紙束を支持した1秒以上の同時走行、車体同士・設備との接触ゼロを必要とします。
